## Key Findings and Lessons Learned

### Piezo Sensor Selection

The DollaTek piezo modules originally specified in the architecture are unsuitable for continuous audio pickup. Their onboard comparator circuit functions as a digital tap detector: it produces a clean pulse on a hard direct tap but gates out sustained or indirect vibrations entirely. Guitar strings plucked in proximity, desk knocks, and voice produced no measurable output.

The correct solution is a raw piezo disc connected directly to a MAX9814 autogain preamp (mic capsule removed, piezo soldered to input pads). This configuration produces a continuous analog signal proportional to contact vibration, suitable for ADC sampling and DSP processing.

The architecture document has been updated accordingly. DollaTek modules are retained as tap-detection triggers if needed elsewhere in the system.

### MAX9814 Configuration

- AR pin floating: 60dB gain (maximum). Correct setting for piezo input.
- DC bias on output: 1.25V (printed on module reverse). ADC baseline reads approximately 290/1023 at rest rather than the theoretical 512.
- Signal polarity: piezo swings negative on impact. Signal is inverted in firmware before processing.
- AGC disabled by leaving TH pin floating. AGC would fight against the distortion effect by automatically reducing gain on loud signals.

### DFPlayer Mini Serial Control

The module supplied (MP3-TF-16P V3.0 with MH2024K chip) has stricter serial requirements than the standard DFPlayer Mini documentation describes:
- Requires a valid two's complement checksum in every packet. Simplified 0x00 checksum is rejected.
- Requires 500ms minimum delay between commands. The standard 30ms causes dropped commands.
- Requires 2000ms boot delay after power-on before accepting commands.
- File naming is strict: files must be named 0001.mp3, 0002.mp3 etc. in the root of a FAT32-formatted card.

### PWM Audio Limitations

Arduino UNO PWM audio output (pin 9, ~62kHz carrier) produces audible buzz artifacts that cannot be fully eliminated with passive RC filtering without also attenuating the audio signal. This is a fundamental hardware limitation of the UNO, not a circuit design issue.

Resolution: PCM5102 I2S DAC modules have been ordered and will replace PWM output in v1.0 on the RP2040-Zero, which has dedicated I2S hardware.

### Power Architecture

All components powered from a single 12V supply:
- PAM8610 amplifier: 12V direct
- Arduino UNO, DFPlayer, MAX9814: 5V via LM2596S buck converter
- Buck converter output verified at 5.000V with calibrated multimeter before connecting sensitive components

Common ground between all components via breadboard GND rail is essential. Without it, serial communication between Arduino and DFPlayer fails.

## Validated Signal Chain

```
Raw piezo disc (contact on surface)
  → MAX9814 preamp (60dB gain, 1.25V DC bias)
  → Arduino A0 (ADC, 10-bit)
  → Firmware: baseline offset, inversion, noise gate
  → Distortion: multiply + hard clip
  → Bitcrush: bitmask resolution reduction
  → Flanger: circular buffer with triangle LFO
  → PWM pin 9 → RC filter (470Ω + 0.1µF + 10µF)
  → PAM8610 Left channel
  → Speaker L

DFPlayer Mini (MP3-TF-16P V3.0)
  → Arduino serial control (pins 10/11 via SoftwareSerial)
  → SPK1 output
  → PAM8610 Right channel
  → Speaker R
```

## Known Limitations

- PWM audio output produces residual buzz. Resolved in v1.0 with PCM5102 I2S DAC.
- Single piezo channel. Final exhibit uses 3x piezo inputs.
- No I2C communication with Brain 1 in this validation. Implemented in v1.0.
- Signal baseline (290) is specific to this MAX9814 module. Recalibrate if hardware changes.
